# 冷库压缩机检修排序规范

## 运行方式

使用交接读数在第 590 分钟为北区冷库排班。运维主管先审阅异常边缘证据，再按机组冗余和班组空档确认短停检修。样例是受控合成流水，包含冲突修订、迟到上报、单位混用、化霜干扰和未完成验修。`capacity` 代表本次最多安排多少台停机，默认为四台。

## 模型与限制

历史窗口按半开区间切分，单机样本不足时回退到设备族基线。压力和振动各用中位数及 MAD 估计中心及波动，波动下限来自仪表分辨率。告警输入是按量纲归一化的压力和向上振动偏离，使用稳定 sigmoid 转成排序分数；样例中的默认曲率和阈值是演示班组策略。超过训练范围的读数先人工量测。单条告警不会派工。

排程按分数、作业截止分钟、设备编号排序，班组占用与冷区停机区间都用半开区间计算。没有独立备用压缩机的维护工单不得自动排入。班次复盘只使用完成且截止前可用的现场结果，把空分桶和无阳性批次显式标成不可计算。

## 告警基准采用

历史工况页面在交班时为每台机组定下本班实际采用的告警基准。旧基准只读取交班截止（`handoff_cutoff`）前的样本，候选新基准在更晚的 `candidate_cutoff` 上重训，可纳入交班后才到齐的迟到样本。两套基准必须用**同一批巡查读数**分别回放稳健异常评分和持续告警，逐机独立决定：

- `LATE_TRAINING_VOLUME`：机组在 `late_trained` 名单中，表示候选基准的训练量是交班后才由迟到样本补足的；即使此刻重训已达标，本班仍沿用旧基准。该判断优先于漂移和告警保护。
- `NEW_BASELINE_NOT_READY`：候选基准压力或振动通道仍不可用，沿用旧基准；两套都不可用时给 `NO_USABLE_BASELINE`，下游读数走 `NO_REFERENCE`。
- `ADOPT_FIRST_BASELINE`：旧基准不可用而候选基准首次可用，没有旧告警需要保护，直接采用。
- `NO_DRIFT_DETECTED`：漂移比较未给出 `REFERENCE_DRIFT`（含 `REFERENCE_STABLE`、`REFERENCE_COHORT_CHANGED`、样本不足等），保留旧基准。
- `UNRESOLVED_ALARM_MASKED`：工况确已漂移，但新基准会让交班时点仍开启且已达持续门槛的告警事件消失；该机组保留旧基准，被盖住的告警按真实触发观测的分钟列出。
- `ADOPT_NEW_BASELINE`：工况确已漂移且换新不丢失任何未解除持续告警，采用新基准。

现场已确认恢复的机组（`field_recovered`）不受告警保护，其旧告警允许随新基准消失。同批中某台机组待复核不影响其他已证实漂移且不丢告警的机组照常换新。本班下游的评分与持续告警统一使用采用决定返回的基准记录（`adopted_references`），采用证据保留两套基准下的峰值评分、持续告警事件和逐机 `fit_id`。

## 业务输出

交接校验逐笔保留处理码。排程表展现机组、冷区、峰值评分、连续次数、班组、停机分钟及原因。评分曲线按机组汇总有效读数，完全无评分机组在该曲线上显示零。校准诊断只用于该班次的模型核对，五个分段保留样本数、预测均值、实际故障比例和误差。

## 复查证据

运行结果的 `reconciliation` 保存读数缺档、参考窗漂移计量、不同阈值的触发对比、持续告警起止、停机计划验算及按班组数重试的候选排程。备用设备、区间冲突和工单截止仍由同一现场约束负责。替代排程优先覆盖高分告警，其次比较工单数和累计完成分钟。历史阈值试算保留未查获成本、误检成本与已确认故障召回区间，仅用于有现场结单结果的样本。

告警基准采用证据（`duty_reference.evaluate_adoption`）逐机保存新旧 `fit_id`、漂移状态、迟到训练与现场恢复标记、两套基准下同一批巡查读数的峰值评分与持续告警事件、被盖住告警的真实观测分钟，以及本班实际采用的基准记录。配套样例 `sample_data/baseline_adoption_evening.json` 覆盖换新、盖住保护、迟到训练、稳定不换、候选不足、首次可用、现场恢复后换新七种采用结果，可由 `tools/generate_adoption_fixture.py` 重新生成并自校验。
